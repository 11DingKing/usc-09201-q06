# 石斛种源追溯网领域约定

项目面向集体林权改革与林下产业协作场景，业务记录需要区分来源、发生时间与当前有效版本。涉及个人、机构或敏感地点的信息只应向职责范围内的角色开放，所有对外结果都应能够追溯到采用的数据版本。

## 核心模型：只追加的事件链

种源事实以事件为单位**只追加（append-only）**，任何已发生事实不得被改写：

| 事件 | 含义 |
| --- | --- |
| `mother_registered` | 母本登记（母本本身也是一个批次） |
| `batch_germinated` | 育苗批出苗，绑定母本 |
| `batch_split` / `batch_merged` | 批次拆分 / 合并，建立血缘边 |
| `inspection_recorded` | 检验结果登记 |
| `inspection_corrected` | 检验更正：旧结果保留但置为失效（`active=false`），新结果生效 |
| `transport_dispatched` / `transport_received` | 跨基地调拨的发出与接收 |
| `planting_recorded` | 林下定植（林地、地块、农户、数量） |
| `quarantine_ordered` / `stock_destroyed` | 隔离暂扣 / 无害化处置 |
| `recall_issued` / `recall_notified` / `recall_acknowledged` | 召回发布、通知送达、执行确认 |

每个事件带三个时间与身份字段：

- `at`：**事实发生时间**，由采集端提供（离线补录时可以是过去时间）；
- `recordedAt`：服务端入账盖戳时间，迟到事件因此可识别；
- `seq` / `eventId`：入账序号与全局幂等编号。

账本投影严格按 `(at, seq)` 归约重建，而不是按入账顺序。因此离线采集的迟到事件按其真实发生时刻参与库存校验，补录既不会改写既有事实，也不会让"事后补一笔销毁"把过去的定植变成超量。

## 不变量

1. **物理标签全局唯一**：`label` 在任意事件顺序下重复都返回 `label_duplicate`（409），与入账时间无关。
2. **检测更正不改事实**：只能对当前仍有效的检验结果更正一次，更正时间不得早于原检时间；反查时始终能看到原结果与更正理由。
3. **库存守恒**：拆分总量、定植量、处置量不得超过按真实时序计算的现存量；隔离库存不可定植、不可调出。
4. **调拨闭环**：整批调拨（部分转运先拆分），必须先发出后接收，在途批次不能重复发出，调出基地须与当前归属一致。
5. **血缘闭包**：拆分/合并形成有向无环血缘图；影响范围 = 触发批次 + 全部下游批次，反查 = 全部上游直至母本。混合批可追溯到多个母本。
6. **召回通知去重**：通知以 `scopeKey`（`farmer:*`、`base:*`、`shipment:*`）为去重单位。同一农户承包多处林地、同一基地持有多个批次都只通知一次；重复发起召回幂等。血缘扩容后可用 `expand` 补发缺失通知。
7. **剩余可用数量**：影响范围内在库且未隔离的数量合计；召回发布时可一键隔离，隔离后剩余可用量归零。

## 分权分区

- 事件链（批次、数量、检验结论、调拨、定植）对业务角色可见，但事件体内**不存放**联系方式与研究记录；
- `research.json`：母本研究数据（海拔、附生环境、育苗基质等），仅 `researcher` / `coordinator` 可读；
- `contacts.json`：农户姓名、电话、承包站点，`coordinator` 全权、`base_operator` 限本基地；其他角色只见编号（`masked`）；
- 事件写权限按角色矩阵控制（见 `src/app.mjs` 的 `WRITE_ROLES`），接口以 `x-user-id` / `x-user-role` / `x-base-id` 请求头识别身份。

## 季末演练口径

把一个育苗批拆往三处林地后补录不合格检测，应能核对：

1. **影响范围**：触发批 + 3 个下游批 + 3 处林地，定植总量、在库余量分别列出；
2. **通知对象**：按农户/基地去重（两处林地属同一农户时只通知一次）；
3. **剩余可用数量**：拆分后留在母批的在库数量，隔离后归零；
4. **执行确认**：各定植点与在库批次逐一确认，重复确认幂等。
